# 첫 마일스톤 검증 보고서

검증일: 2026-09-26. 대상: Linux x86-64, Ubuntu 24.04의 WSL2 환경.

## 결과

독립 Rust 엔진의 첫 구현을 완료했다. 숫자·문자 배열, 기본 산술·형상 연산, 명사 바인딩, 제한된 reduction·monadic rank를 CLI와 스크립트로 실행한다. C 엔진 fallback은 없다.

| 검증 | 결과 |
|---|---|
| Linux release 빌드 | 성공 |
| rustfmt / Clippy 경고 오류 처리 | 통과 |
| Rust 단위·통합 테스트 | 11개 통과 |
| 실제 J와 차등 비교 | 362개 통과, 실패 0, 제외 0 |
| 이름 공유 후 원본 보존 | 통과 |
| 단독 소유 데이터 포인터 재사용 | 통과 |
| CLI 오류 코드·상태 유지 | 통과 |
| 1,000개 제한된 malformed 입력 | panic 없이 완료 |
| release 실행 파일 | Linux ELF x86-64 |
| J 라이브러리 링크 | 없음 |

`ldd` 결과에는 libc, libgcc_s와 Linux loader만 나타났다. 이는 J의 C 엔진을 사용하지 않는다는 의미이며 운영체제의 C 런타임까지 제거했다는 의미는 아니다.

차등 검증은 직접 작성한 M1 사례와 고정 seed 생성 입력이다. 기존 jsource 전체 테스트 파일 실행이나 전체 J 호환성 검증이 아니다. Oracle은 별도 Python 프로세스에서 고정 커밋의 C 라이브러리를 호출하며 JSON으로 값을 전달한다.

## 성능 기준선

CPU: Intel N150. Rust 1.98.0, GCC 13.3.0. release 빌드, CPU별 native 플래그 없음. 워밍업 후 3회 측정 중앙값이며 시작·출력 시간은 제외한다.

단위: 마이크로초/연산.

| 원소 수 | Rust 바인딩 배열 덧셈 | C 참조 바인딩 배열 덧셈 | Rust 소유권 전달 커널 |
|---:|---:|---:|---:|
| 16 | 0.919 | 1.827 | 0.174 |
| 100,000 | 164.743 | 78.014 | 102.638 |
| 1,000,000 | 2,620.943 | 1,498.591 | 1,649.330 |

바인딩 배열 작업은 양쪽에서 `r =: a + 2`를 실행한다. C 쪽은 Python ctypes/JDo 호출 비용이 포함되므로 특히 작은 입력의 직접 비교는 부적절하다. 참조 빌드는 기본 j64이며 PYXES, SLEEF, EMU_AVX를 껐다. 최고 성능 upstream 설정과의 비교가 아니다. 소유권 전달은 Rust 커널 직접 호출이며 C 쪽 대응 수치는 없다.

큰 배열의 바인딩 덧셈은 현재 Rust가 이 C 기준선보다 느리다. 첫 구현에서 성능 우위를 달성했다는 주장은 하지 않는다. 정수 overflow 사전 검사, 공유 버퍼 복사와 일반 실행 경로가 후속 최적화 대상이다. 아직 프로파일러로 각 비용의 비중을 확정하지 않았다.

## 할당 측정

시간 측정과 별도로 워밍업된 연산 한 번을 계측했다. System allocator 요청 기준이며 크기에는 메타데이터를 포함한다. peak는 작업 시작 시점의 live bytes 대비 추가 최대치이며 RSS가 아니다.

| 작업 | 원소 수 | 할당/재할당 요청 수 | 누적 할당 바이트 | 추가 live bytes 최대 |
|---|---:|---:|---:|---:|
| 바인딩 배열 덧셈 | 16 | 17 | 1,031 | 773 |
| 바인딩 배열 덧셈 | 100,000 | 17 | 800,903 | 800,645 |
| 바인딩 배열 덧셈 | 1,000,000 | 17 | 8,000,903 | 8,000,645 |
| 소유권 전달 덧셈 | 16 | 4 | 96 | 56 |
| 소유권 전달 덧셈 | 100,000 | 4 | 96 | 56 |
| 소유권 전달 덧셈 | 1,000,000 | 4 | 96 | 56 |

소유권 전달 경로는 배열 크기와 무관한 작은 할당만 수행하고 데이터 버퍼를 재사용한다. 바인딩 원본을 보존해야 하는 경로는 새 데이터 버퍼를 할당한다. 전체 엔진이 allocation-free인 것은 아니다. C의 할당량과 복사 바이트는 이번에 측정하지 않았다.

## 남은 범위

- 전체 J 파서, 함수·train·locale·일반 수정자
- 박스·희소·복소수·확장 정밀도와 시스템 기능
- rank 빈 frame의 prototype과 결과 padding
- reduction/rank의 중간 할당 제거
- 단독 소유 저장소와 공유 저장소의 분리
- SIMD·병렬화·메모리 풀
- 정확한 텍스트 포맷, 광범위한 수치 경계 호환성
- 네이티브 Linux 별도 머신, ARM64, sanitizer/Miri와 원격 CI 검증

우선 다음 단계에서 지원 의미의 경계를 넓히고, reduction의 반복 할당을 제거한다. 이후 더 넓은 실제 작업군으로 성능을 측정해야 한다.
