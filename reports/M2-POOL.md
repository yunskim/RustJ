# CPU 정수 출력 풀

2026-09-26. CUDA 구현은 사용자 요청으로 보류했다. Linux CPU 작업을 계속한다.

## 구현 범위

Engine별 출력 풀을 정수 add/sub/mul의 새 출력 경로에 연결했다. 기존 단독 소유 입력 재사용과 AVX2 경로는 유지한다. 대입이 성공한 후 이전 바인딩을 회수하며, Arc::try_unwrap이 성공한 버퍼만 보관한다. 별칭이나 호출자가 보유한 값은 변경하지 않는다. 실패한 대입은 기존 값을 보존한다.

기본 보유 상한은 payload capacity 합계 64 MiB, 최대 16개 버퍼다. 1 KiB 미만은 보관하지 않고 정확히 같은 capacity만 재사용한다. 이 값들은 최적화된 임계값이 아니라 보수적인 초기 정책이다. 상한보다 큰 버퍼는 allocator에 반환한다. 풀 메타데이터·살아 있는 배열·allocator가 보유한 메모리는 이 상한에 포함되지 않는다. 프로세스 RSS 상한을 뜻하지 않는다.

`Engine::with_output_cache_limit(bytes)`로 상한을 지정하며 0이면 비활성화한다. `output_cache_stats()`는 보유 payload bytes와 누적 hit 수를 제공한다. `clear_output_cache()`는 보유 버퍼를 allocator에 반환하며 RSS 감소는 보장하지 않는다. 실수·문자·불리언 출력, scratch, rank 조립 및 임시 값의 자동 회수는 이번 범위에 없다. 오버플로 시 정수 출력은 버리고 기존 입력으로 실수 결과를 다시 계산한다.

## 검증

Linux WSL Ubuntu, Rust 1.98.0, Intel N150. 기본 및 portable 각각 일반 테스트 23개와 compile-fail 문서 테스트 1개 통과. rustfmt 및 clippy --all-targets -D warnings 통과. C 기준선과 차등 비교 464/464 통과(전체 upstream J 테스트는 아님).

추가 테스트는 실제 반복 대입에서 풀 비활성 대비 회당 힙 할당 1회 감소, 살아 있는 별칭과 외부 반환 값 보존, 실패한 대입, 여러 크기의 보유 상한, 초기화된 결과, 정수 overflow 전체 실수 승격, 비활성화 및 명시적 비우기를 검증한다.

## 첫 성능 측정

`taskset -c 0 cargo bench --bench pool`: 동일 프로세스에서 캐시 off/on 엔진을 준비하고 `r=:a+2`를 반복한다. 워밍업 4회, 8라운드 교대 순서, 라운드 중앙값. 4096원소는 라운드당 10000회, 나머지는 100회. 시간 단위는 마이크로초/평가다. 할당 계측은 별도 테스트에서 수행한다.

| 원소 수 | 캐시 off | 캐시 on | on 보유 payload |
|---:|---:|---:|---:|
| 4,096 | 1.877 | 1.996 | 32,768 B |
| 1,000,000 | 1,333.782 | 1,263.320 | 8,000,000 B |
| 4,000,000 | 5,322.463 | 5,089.195 | 32,000,000 B |

이번 측정에서 큰 두 배열은 약 5.3%, 4.4% 개선됐지만 작은 배열은 약 6.3% 느려졌다. 단일 장비·실행의 제한된 결과이며 일반적인 가속이나 C 대비 우위를 뜻하지 않는다. 작은 배열 제외 임계값 변경은 반복 측정 후 결정한다. 동일 용량 재사용으로 크기가 자주 바뀌는 작업의 적중률은 낮을 수 있다.

## 다음 CPU 작업

실수 출력 풀은 별도 typed pool로 확장할지 측정 후 결정한다. scratch는 실제 소비자가 생기는 연산과 함께 도입한다. 이어서 빈 frame prototype·dyadic rank·결과 padding 의미를 C와 차등 검증하며 확장한다. CUDA는 현재 구현하지 않는다.
